# Visitor ID: хто заходив на сайт

Встановити як скіл Claude Code (Claude сам розгорне все, що нижче):

```bash
npx skills add victor-shulga/visitor-id
```

Або руками: `git clone https://github.com/victor-shulga/visitor-id.git && cd visitor-id`, далі розділ «Встановлення».

Візит на сайт є сигналом інтенту: людина вже знає про вас. Цей репозиторій збирає візити в одну базу і віддає їх в аутріч тим самим CSV, що й [сигнал-радар](https://github.com/victor-shulga/signal-radar-starter): компанія, дата, сторінка-доказ, черга A/B.

## Що реально можна дізнатися

| Шлях | Що отримуєте | Де працює | Ціна |
|---|---|---|---|
| **RB2B** | людину: ім'я, посада, LinkedIn, компанія | лише відвідувачі зі США | безкоштовний план → Slack; вебхук на платному |
| **Компанія за IP** (LinkedIn Insight Tag, Snitcher, Leadfeeder, Dealfront) | лише компанію | будь-яка країна, офісний трафік | від $0 до ~$100/міс |
| **Свої посилання з міткою** (`?ref=<id>` у листах, вхід через LinkedIn на лід-магніті) | людину, яку ви вже знаєте | будь-яка країна | $0 |

Людину за візитом RB2B визначає через cookie трьох рекламних мереж США: вони повертають хеш пошти, якщо вже бачили цей браузер. За межами США цього не повторити ні технічно, ні законно, тому для Європи працюють лише компанія за IP і свої мітки.

## Requirements & integrations

| Integration | Used for | Required? | Auth/setup |
|---|---|---|---|
| RB2B або інший інструмент з вебхуком | візити | так, один із | вебхук на `https://<ваш-воркер>/hook/<HOOK_SECRET>` |
| Cloudflare Workers + D1 | прийом і зберігання візитів | так | `npx wrangler login` |
| Slack | безкоштовний план RB2B шле лише сюди | ні | канал RB2B → Claude читає його щодня |
| python3, node | експорт і тести | так | не потрібно |

## Файли

| Файл | Що робить |
|---|---|
| `worker.js` | приймає вебхук, пише візит у D1, завжди швидко відповідає 200 |
| `schema.sql` | таблиця `visit` |
| `wrangler.toml` | назва воркера і база |
| `export.py` | візити за N днів → `state/visitor_signals.csv` у форматі сигналів радара |
| `test.mjs`, `test_export.py` | перевірки без мережі |
| `skills/visitor-id/SKILL.md` | скіл: Claude проводить через встановлення, джерело і щотижневий експорт |

## Встановлення

```bash
node test.mjs && python3 test_export.py        # visitor-id test ok, export test ok
npx wrangler login
npx wrangler d1 create visitor-id               # database_id → wrangler.toml
npx wrangler d1 execute visitor-id --remote --file=schema.sql
npx wrangler secret put HOOK_SECRET             # довгий випадковий рядок
npx wrangler deploy
```

Далі в RB2B: Integrations → Webhook → адреса `https://visitor-id.<ваш-акаунт>.workers.dev/hook/<HOOK_SECRET>`. Перевірка: `curl https://.../health` повертає `ok`.

RB2B вимикає інтеграцію, якщо відповідь не 200 або довша за 15 секунд, тому воркер нічого не рахує, лише записує.

**Безкоштовний план RB2B (лише Slack).** Вебхука немає. Поставте Claude щоденну задачу: «Прочитай канал RB2B у Slack за вчора, кожне повідомлення перетвори на JSON з полями LinkedIn URL, First Name, Last Name, Title, Company Name, Website, Captured URL, Seen At і надішли POST на адресу хука». Далі все так само.

**Компанія за IP.** Більшість таких інструментів теж уміє вебхук або CSV. Поля `Company Name`, `Website`, `Captured URL`, `Seen At`, цього достатньо, воркер приймає візит без людини.

## Мітки: звідки прийшов візит

Без міток видно лише сторінку. З мітками видно, з якого каналу і якої кампанії прийшла людина, а з `ref` ще й хто саме. Мітки працюють у будь-якій країні: тут не треба ні RB2B, ні IP.

Два види міток:

| Мітка | Що каже | Приклад |
|---|---|---|
| `utm_source` | канал | `linkedin`, `email`, `post`, `signature`, `leadmagnet` |
| `utm_medium` | тип дотику | `outreach`, `organic`, `dm` |
| `utm_campaign` | гіпотеза або кампанія, тією ж назвою, що в HeyReach чи Instantly | `long-hiring` |
| `ref` | конкретний контакт: його ID у CRM | `ref=48213` |

Правила: латиниця, малі літери, дефіс замість пробілу. Одна назва кампанії скрізь: у розсилці, в мітці, в CRM. Інакше їх не зведеш.

**Куди ставити**

| Де посилання | Шаблон |
|---|---|
| лист в Instantly | `https://site.com/cases?utm_source=email&utm_medium=outreach&utm_campaign=long-hiring&ref={{crm_id}}` |
| повідомлення в HeyReach | `https://site.com/cases?utm_source=linkedin&utm_medium=outreach&utm_campaign=long-hiring&ref={crm_id}` |
| пост у LinkedIn | `https://site.com/offer?utm_source=post&utm_medium=organic&utm_campaign=2026-11-26` |
| підпис у пошті | `https://site.com/?utm_source=signature&utm_medium=email` |
| лід-магніт в особистих | `https://site.com/guide?utm_source=leadmagnet&utm_medium=dm&ref={crm_id}` |

`{{crm_id}}` і `{crm_id}` — це власне поле контакту в розсилці. Заведіть його при завантаженні списку і кладіть туди ID контакту з HubSpot.

**Ніколи не кладіть у посилання пошту чи ім'я людини.** Адреса потрапляє в логи, аналітику й чужі пересилання. Лише ID, за яким людину знайдете тільки ви.

Внутрішні посилання сайту міток не мають: мітка на переході між вашими сторінками затирає справжнє джерело.

**Що буде в CSV.** `export.py` читає мітки з адреси сторінки і додає колонки `utm_source`, `utm_campaign`, `ref`. Візит із `ref` означає, що відома людина повернулась. Він завжди йде в чергу A, навіть якщо ні RB2B, ні IP компанію не впізнали.

**Заявки з форми.** Якщо на сайті стоїть код відстеження HubSpot, UTM візиту, після якого людина лишила заявку, HubSpot записує в джерело контакту сам. Так видно, яка кампанія привела заявку.

## Як візит іде в аутріч

```bash
python3 export.py --days 7
```

- **A**: дивився ціни, кейси, контакти чи послуги, або заходив 3+ рази. Пишемо цього тижня.
- **B**: решта. Чекаємо другого сигналу.

Перед листом компанія проходить ті самі стоп-фільтри, що й решта: ICP, розмір, поточні клієнти, конкуренти. Людину без LinkedIn шукаємо як ОПР під компанією.

**Не пишіть, що бачили людину на сайті.** Вона про це не знає, і такий початок відштовхує. Привід для листа: тема сторінки, яку вона дивилась.
